## 사용자 의견에 대한 설계 결정

1. **2인 책상 통과 문제:** 기존 `pathIn/pathOut`은 가까운 열 사이로 단순 이동하여, 공유 테이블 내부 경계가 통로로 잘못 선택될 수 있었음. 30석에 한해 `safeRoute30` / `pathClear30`을 도입. 공유 책상 내부 이음매는 제외하고, 독립된 중간 통로를 선택. 책상·의자 AABB를 생성하고 약 0.24m 캐릭터 반경을 고려하여 전 이동 구간을 약 0.075m 간격으로 검사. 단, 목적지 의자 접근 마지막 구간은 자체 의자/책상에서 예외. 통로 없으면 서버 착석 요청 전에 차단.
2. **처음부터 캐릭터:** 서버 착석과 무관한 로컬 방문자 아바타를 입구에 배치(공부 기록·좌석 점유 없음). 실제 착석이 완료되면 그 아바타를 제거하고 서버 연동 캐릭터로 교체. 다른 사용자에게는 로컬 캐릭터가 표시되지 않음.
3. **초기 시점:** 순수 1인칭 대신 캐릭터가 보이는 **3인칭 입구 시점**. 네 번째 벽 출입문을 통해 방을 바라보며, 좌석을 선택하면 걷는 캐릭터를 따라가고, 도착하면 책상 시점으로 전환. 필요하면 상단의 30석 목록/전체 보기/입구/바다 버튼으로 전환.
4. **도서관 네 번째 면:** 카메라 쪽 입구 벽에 실체가 있는 책장, 문틀, 벽기둥, 문 위 처마를 설치. **전체 조망 모드에서는 책장 벽을 숨기고 구조 외곽만 남기는 컷어웨이(cutaway)** 방식이라 좌석 선택에 방해하지 않음. 입구/걷기/책상/창밖 시점에서는 네 번째 벽이 나타남.

## 수행한 검증

- GitHub에서 최종 HTML 불러오기, 인라인 JS 문법 검사 **PASS**.
- PC 1200×800, 모바일 390×844, 소형 모바일 320×700 각각에서 공용/학교 30석의 **총 180개 경로**(30석×6조합)를 0.24m 충돌 여유로 검증: 실패 0.
- PC 통로 x=-2.1,2.1, 세로 모바일 통로 x=0.925를 선택. 공유 테이블 내부 이음매를 통로로 사용하지 않음. DB 좌석 번호 0~29 변경 없음.
- 별도 Three.js 유사 객체 모의 테스트: PC·모바일의 30석 공용/학교 방에 전면 책장벽과 입구 아바타 생성 확인; 기존 12석 방에는 신규 벽/아바타를 추가하지 않음; 전체 보기 시 전면 벽 숨김, 입구 시점에 다시 나타남.
- 입구 시점 카메라가 전면 출입문을 통과해 캐릭터를 바라보도록 구성. 투영 화각에 따른 PC/모바일 머리·몸통·발 위치를 계산해 초기 구도 조정.
- 화면 회전 중 착석 애니메이션이 초기화되더라도 완료 콜백이 유지되어 공부 시작 함수가 누락되지 않도록 변경.
- 모든 변경은 고립된 신규 경로에만 커밋. 운영 DB/RPC/사용자 데이터 변경 없음.

## 제한과 미검증

- **실제 Chrome/WebGL 스크린샷·실제 FPS·GPU 자원 지표는 이 작업에서 테스트하지 못함.** 코드 모의 검사로 외형 품질 보증 불가.
- 아바타가 전면 문틀에 가리는지, 일부 구간에서 3D 모델이 충돌해 보이는지, 실제 세로 기기에서 문자/컨트롤과 겹치는지 확인 필요.
- 캐릭터 이동 경로의 `pathClear30`은 책상·의자 중심 안전 거리 검사. 사람들끼리의 충돌 회피나 플랜터·소품과의 정밀 물리 충돌은 구현하지 않음.
- 30명 동시 입장/Realtime/실기기 성능/실제 Supabase 시간 기록은 이 버전에서 새로 실측하지 않음.
- 캐릭터 직접 자유 이동(WASD)은 의도적으로 추가하지 않음. 공부 시작 전 체험 아바타는 자리 점유 없이 입구에 정지함.
- 이전에 지적됐던 레거시 RPC, 학교 Realtime 권한, 미성년 사용자 개인정보 안내 등 정식 배포 차단 요인은 남아 있음.
