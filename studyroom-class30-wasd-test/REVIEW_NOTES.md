# STUDY ROOM 30석 — WASD 자유 이동 추가 검수 기록

**시험판:** https://gtmc-history.github.io/studyroom-class30-wasd-test/

**변경 대상:** `studyroom-class30-wasd-test/index.html`만. 이전 `studyroom-class30-pov-review/` 및 운영판, Supabase DB/RPC/Realtime 권한은 수정하지 않았음.

## 변경 목적과 조작
기존 `studyroom-class30-pov-review`는 입장 시 캐릭터를 보여주었지만 직접 이동할 수 없었음. 기존 구현의 자유 이동 부재를 수정함.
- W, A, S, D / 방향키: 전후좌우 이동. 대각선은 정규화, 이동속도 2.55 월드단위/초, 프레임 변동 대비 0.08 이하의 하위 이동 단위 적용
- 캐릭터가 움직이면 카메라는 3인칭 탐색 모드(`explore`)로 따라감
- 키를 누르고 있는 동안 발·팔 걷기 애니메이션, 막히면 멈춤; 슬라이딩 동작 포함
- 30석 공간의 책상·2인 테이블·의자 충돌 AABB 및 캐릭터 반경 0.26 적용. 벽/바닥 가장자리도 넘지 못함
- E: 근처 1.65m 이내 좌석의 착석 메뉴만 호출(서버 착석은 기존 버튼 확인을 거쳐야 함)
- 좌석 점유 중, 모달 입력 중, 브라우저 포커스 이탈, 방 전환에는 자유 이동 중지/키 상태 해제
- 👤 따라가기 버튼으로 탐색 시점 복귀. 좌석 선택 후 기존 안전 통로 자동 이동과 역사/공부 기록 흐름 유지
- 로컬 방문자 캐릭터의 위치는 **브라우저 내부 시각 상태**이고 별도 DB 저장·다른 이용자 실시간 전송 없음

## 자체 검수 — 코드/수학 모의 실행
1. PC 1200×800 및 모바일 390×844: KeyW 전진과 KeyA 좌측 이동이 아바타 좌표를 실제 변경, 후방 3인칭 카메라도 `explore` 모드로 전환함
2. 방향키 ArrowUp 또한 이동하고 기본 동작 방지 확인
3. 2인 책상 내부의 중앙 경계는 충돌 처리되고 별도 통로는 열려 있음. PC/모바일 각 배치 통과
4. 책상에 접근하면 막히며 해당 위치가 장애물 내부에 진입하지 않음. 막혔을 때 제자리 걷기 오동작 수정
5. 이미 좌석에 앉은 상태에서 자유 이동 입력 비활성화. 문자 입력 필드에는 키 조작이 개입하지 않음
6. 가까운 좌석에서 E키 착석 선택 호출 확인
7. GitHub 저장된 전체 인라인 JS 구문 검사 통과

## 미검증 사항
- 실제 GitHub Pages 주소가 브라우저에서 정상 로드되는지는 이 환경에서 확인하지 못함
- 헤드리스 Chrome/실제 휴대폰에서 캐릭터/카메라의 화면 움직임·프레임 속도·WebGL 리소스는 검증하지 않았음
- 충돌은 책상/의자/벽의 단순 사각형 모델; 식물·다른 이용자·세밀한 장식품과의 물리 충돌은 없음
- 자유 이동은 **착석 전 로컬 캐릭터**에만 적용. 공부 중 자리를 임의로 떠나 이동하는 기능은 없음
- 원래의 서버 Realtime, 아동 개인정보 안내, 30명 동시접속 등 정식 공개 차단 문제는 해결하지 않았음

## 독립 재검수 요청
1. 로컬/헤드리스 Chrome에서 입장 후 **WASD를 길게 누르면 실제로 캐릭터와 카메라가 이동하는지**, 키를 놓으면 멈추는지 확인
2. 2인 책상 중앙을 향해 걸을 때 통과하지 않는지, 독립 통로는 이동 가능한지 영상으로 확인
3. 30석 공용/학교 방 PC/모바일 오리엔테이션별 시점 및 캐릭터 끼임, E키 상호작용
4. 교사가 입력 중인 폼·모달에서 WASD가 가로채지 않는지, 좌석 착석 후 WASD 비활성화 확인
5. 30명 동시 접속, 공부 기록·서버 동기화 문제는 별도 배포 QA로 재검증
